# RoboBuild architecture

Status: shared architecture implemented for the four interactive LEGO workbenches; the VEX catalog entry is source/rights-blocked, and none of the authored full assemblies is physically fit-certified. This architecture is **not** a claim that the five-robot product is complete. See [current coverage](../validation/coverage-baseline.md), [product specification](../specifications/product.md), [assembly engine](../specifications/assembly-engine.md), [geometry pipeline](../specifications/geometry-pipeline.md), [simulation](../specifications/simulation.md), and [fidelity requirements](../research/fidelity-requirements.md).

## Small deep modules

Keep data, time evaluation, geometry, rendering and UI separate. One viewer/engine/timeline serves every build; a new robot mainly adds a validated manifest, asset crosswalk/BOM, steps/operations, hierarchy/joints and optional scenario tracks. Do not add dependency injection frameworks, per-robot viewer subclasses, plugin registries, event buses or a separate scene-state store beside the sampled frame.

| Implemented module / offline input | Owns | Does not own |
| --- | --- | --- |
| `src/lib/types/model.ts` | Pure shared declarations and exact required user fields; evidence/coverage, frames and module interfaces | Robot values, Three.js imports, loading or runtime stubs |
| `src/lib/models/catalog.ts` and model manifest files | Five identities/editions, available or blocked catalog metadata, model data references | Fetching arbitrary assets or manufacturing unverified counts |
| `src/lib/assembly/engine.ts` | Compile-time validation, hierarchy/event/trajectory compilation, absolute-time sampling and step queries | Wall clock, camera state, Svelte, GPU resources |
| `src/lib/geometry/cache.ts` | Licensed asset/dependency loading, retained shared geometry and attribution | Assembly time, inventory counters or robot-specific placement corrections |
| `src/lib/scene/controller.ts` | One Three.js/WebGL2 scene, camera/controls, instancing, picking, rendering modes and resource lifetime | Recounting parts, inventing poses or advancing assembly time |
| `src/lib/simulation/kinematics.ts` | Same-hierarchy joint evaluation, deterministic command/sensor/object tracks | Replacement robot models or unvalidated physics claims |
| `src/lib/components/` and `src/routes/+page.svelte` | Catalog/workbench/transport/panels, accessible DOM, finite time/playback state, selection, readable evidence/errors | Three.js node mutation outside controller or duplicate animation logic |
| Offline asset/data scripts | Authorized conversion, closure/hash/attribution and model validation artifacts | Browser-critical STEP parsing or bypassing permission blockers |

These are concrete responsibility assignments, not a requirement to create empty directories/classes. A module earns its seam by hiding substantial behavior: assembly callers provide a model/time/frame and receive the whole deterministic assembly; renderer callers provide that derived frame rather than a queue of per-part commands.

## Shared schema and authoring invariants

The schema preserves the original `PartInstance`, `SourceReference`, and `AssemblyOperation` fields verbatim in name, optionality and value domains. Added fields supply staging, evidence, motion stages, installation events and hierarchy changes. `partNumber` is a verified manufacturer identity when known; `geometryId` identifies a real asset, not catalog certification. Never derive one by stripping `.dat` from the other. `geometryConfidence`/source confidence are finite `[0,1]` evidence ratings, not completion percentages or physical accuracy measurements.

`Transform` is right-handed Y-up scene millimeters, normalized quaternion xyzw and scale xyz (unit by default). Preserve native part origins. LDraw assets use one documented0.4mm/LDU and rotationXπ conversion; native placement conversion is `N*T*N^-1`, with no recentering. `initialTransform`/`finalTransform` and operation endpoint arrays are world-space scene poses. Structural child transforms/connection frames are local as explicitly named. Numeric source transforms and qualitative documented relationships have independent provenance. Camera presets are presentation-only.

Every actual inventory instance is stable across staging, playback, merges, selection, explosion and simulation. `partInstanceIds`, `fromTransforms`, `toTransforms` must have matching lengths and order. Each operation has one step, explicit dependencies and step-relative start/duration. Stages are operation-relative, ordered and contained within its duration. Stage node endpoint arrays match `nodes` in order. A subassembly stage targets its root once; operation part endpoint arrays still describe the affected inventory instances' corresponding world start/end snapshots, allowing audits without double-driving those children. Ordinary simple operations use a single part stage. No concurrent writer may also animate one of a moving root's descendants.

At operation completion, explicit parent changes commit together, preserving world pose through parent-local endpoint records. Before completion the participant follows its world-space stage track; unchanged descendants retain their local transforms. Validate parents and any switch at each event, not only the final hierarchy. `Subassembly.partInstanceIds` lists directly owned parts, `childSubassemblyIds` lists direct children, and `parentId` is reciprocal. `PartInstance.subassemblyId` identifies its initial structural parent; parent changes supply later membership. Final world poses must equal declared `finalTransform` after all operations. Reused modules never mint additional inventory identities.

A documented camera-only step has a presentation-only `align` operation, empty part/transform/stage arrays, a camera preset and source evidence. It satisfies the documented-step mapping without inventing physical movement. Other zero-part/no-effect operations are rejected. Reference-only pages are source mappings without a step; unnumbered preparation is not fabricated numbered instruction. Installation milestones occur once per inventory instance at first seating into its prepared assembly, including intra-step events; merges do not recount. Initial staging is visible by default; visibility milestones can change staging without changing installed state. Compile checks installation coverage against the manifest's explicitly supported inventory, not a presumed full-kit count.

Inventory lines explicitly separate prepared callout units, printed inventory, step additions and CAD occurrences. Only the manifest's selected count basis maps one-to-one to tracked instances and frame counts; conflicting alternative records remain evidence and must not be summed. Captive cables remain within prepared devices. A separately counted cable must identify its own instance; rendering a route is not a new physical item. Source-backed inventory scope is robot versus loose samples. Coverage exposes documented/implemented/verified steps, modeled/verified components, geometry confidence and outstanding deviations; these are not interchangeable.

## Loading and frame flow

1. Catalog metadata loads without geometry. A blocked entry displays official source links, selected edition, coverage, blockers and retained required scenario; its type forbids model/preview URLs. Never synthesize a VEX robot preview from unauthorized CAD or stock geometry.
2. Selecting an available entry pauses transport, resolves its own manifest, validates/compiles once, allocates one assembly frame, then calls `RendererController.loadModel(model)`. Show loading/error states and cancel stale model adoption; no previous model's scene may be mislabeled as the new one.
3. The workspace owns `timeMs`, playback mode (`paused`, `step`, `all`, `reverse`), speed, selection and view options. On transport/animation clock input it calculates one finite time and calls `sampleAssembly(compiled,timeMs,frame)`. Frame buffers are reused, not inserted as a fresh deep reactive tree every tick.
4. Controller `update(frame)` reads the derived transforms/flags and updates retained matrices/highlights. It does not hold a reference and then observe unsignaled mutation: each explicit update consumes the current frame. DOM summaries update the small step/count/provenance fields, not all meshes.
5. At complete supported assembly, simulation compiles that same hierarchy/scenario, samples a reusable simulation frame, and passes `simulationFrame.assembly` through the same controller. Leaving simulation restores the saved assembly time/view; no count or manifest mutation leaks back.
6. Switching model or destroying the workspace releases resources, listeners, controls, scheduled callbacks and geometry acquisitions. A late async result cannot revive a disposed/replaced model.

Finite time validation precedes buffer mutation; all references, DAG constraints and endpoints validate at compilation. Failures are actionable evidence, not swallowed promises or placeholder meshes. The SvelteKit server handles catalog/document metadata without importing/constructing WebGL; mount the renderer only in the browser. Detect WebGL2 failure and retain accessible sources/inventory/error guidance, not a fake working canvas.

## Renderer controller and UI seam

Construct the controller in the browser with the canvas/container, geometry cache and `RendererCallbacks`; construction belongs to the concrete Three.js module, not a generic factory hierarchy. The shared interface is `loadModel(model)`, `update(frame)`, `select(id|null)`, `setView(options)`, `fit(target)`, `resetCamera()`, `setAutoCamera(enabled)` and `dispose()`. Callbacks report stable picked instance IDs, manual camera override, and actionable errors. Programmatic `select` never re-emits itself as a new user pick. Unknown instance/subassembly IDs are errors rather than selecting an arbitrary mesh.

`ViewOptions.mode` is studio, technical or inspection; `explodedFactor` is independent `[0,1]`, with labels/axes/connections/isolation toggles. Studio uses restrained original PBR lighting, controlled tone mapping, soft shadows and antialiasing. Technical keeps mechanical lines/holes and high-contrast selected outlines legible. Inspection adds actual IDs, mounting points/relationships and isolate; selected geometry has both a visible outline and text inspector, not color alone. Explosion derives meaningful mechanical separation vectors from connections/subassemblies and overlays the sampled pose without writing it back. All modes share the same part transforms/installed state. No permanently duplicated per-robot renderer scenes or decorative controls.

Renderer owns orbit/zoom/pan, camera easing and user override. Authored camera presets are presentation-only, never part transforms. Manual orbit/pan/zoom immediately disables auto transitions and reports the override; future sampled steps do not fight the user. `resetCamera()` returns to the current authored framing without re-enabling auto; an explicit Resume auto camera calls `setAutoCamera(true)`. Fit whole/active/subassembly is immediate user intent and preserves time. In reduced motion, jump camera transitions and avoid continuous explosion animation while retaining fit/inspection and correct final state. Clear override when a different model is explicitly loaded.

UI owns Play step to next source boundary, Play all to final, Reverse to zero, Pause, Previous/Next and seek/speed/milestones. Previous from a fractional step goes to its start, from a boundary to the preceding boundary; Next goes to the next boundary. Manual seek pauses first. Source-page reading stays independent; only an explicitly mapped figure seeks its step. DOM controls have labels, keyboard/focus behavior and live current-step/count summaries without per-frame screen-reader chatter. Keyboard shortcuts never intercept typing; no canvas-only action is required.

## Completion and evidence gates

Locked research totals: ADB136steps/234prepared units; Hand28/39; Quality30/55robot+8sample units; Sorter index2019 77robot+3sample steps/158+8units. Those are scoped arithmetic callout sums, not full set or certified manufacturer BOMs. VEX historical2018 has41steps with preserved conflicting inventory records and a preassembled claw; native CAD occurrence counts are not procurement totals. Public app use/conversion of its official STEP remains blocked. Keep Rev6 and lesson2021 alternate research separate.

Every robot still owes all12 exact acceptance criteria from the product/testing specification, complete source-linked data and validated placement, functional full required scenario, automated tests, licenses and honest coverage. The real-geometry ADB bracket is an implementation sequence, not permission to narrow the goal. Critical missing placement/evidence/rights blocks the affected capability and remains in coverage; never mark a smaller goal complete. The [current coverage ledger](../validation/coverage-baseline.md), not these architectural invariants, records actual build, unit, WebGL/browser and source-fit evidence.
