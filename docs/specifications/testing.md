# RoboBuild acceptance and testing specification

Status: verification specification, not a test report. Four interactive LEGO models now exist; actual gate outcomes and unresolved fit/permission constraints are recorded in the [coverage ledger](../validation/coverage-baseline.md) and per-model validation reports. Section **18** of the handoff contains **12** acceptance criteria; all 12 apply to every build. Additional interaction, accessibility and resource checks below preserve the rest of the handoff, not a reduced interpretation of those criteria.

## Evidence rules and execution contract

Keep documentation, implementation and verification separate. A source-transcribed step is documented; it is implemented only when its actual operations, instances, geometry and source mapping are consumed by the runtime; it is verified only when automated invariants and relevant visual/mechanical review pass with recorded evidence. A generated manifest, declared field, successful import or screenshot of a generic object is not implementation/verification of a robot.

Every result records build ID, edition, source hashes, implementation revision, test/capture ID, exact timestamp/source step, browser/device/OS, viewport, render mode, assertions, outcome and outstanding deviations. Screenshots are generated from the actual app. Compare source-aligned representative views privately, with explicit overlays/notes for occlusion and diagram-derived uncertainty; do not publish manual images. Record tolerances with units and their source before evaluating placement. Do not choose loose tolerances merely to make a failing model pass. Valid designed contact/interference, such as a friction pin, is distinguished from unintended intersection.

Use the existing project runner when implemented, with small permanent tests near the engine/data/simulation consumers and Playwright for browser workflows. Proposed package-script contracts are `test:unit`, `test:e2e`, `test:perf`, `check` and `build`; these commands are **not present or claimed runnable at this baseline**. The implementation phase must connect actual scripts before citing them as verification. `test:unit` runs schema/BOM/graph/timeline/consumer tests against shipped manifests; `test:e2e` starts the app and exercises the flows below; `test:perf` records a real browser trace/resource report on declared hardware. Type checking/build success is necessary but cannot establish assembly fidelity.

Permanent tests target behavior at consumers: e.g. compile and sample a real operation, select a rendered instance, update an actual source panel, reset a real simulation. Do not test only that data fields exist, callbacks are wired, or mocks return their configured values. Use the real engine, renderer adapter and manifests; a tiny analytic two-part fixture may isolate a mathematical regression, but never substitute for per-model coverage. No giant mock robot graphs or mock Three.js scene that can conceal transform/camera/picking bugs. Add a focused regression for each discovered consumer bug.

## Section 18 acceptance matrix: exact criteria

Each row is required independently for **Advanced Driving Base, Robot Hand, Quality Check Robot, Package Sorter index2019 and V5 Clawbot historical2018**. A complete row on one robot does not establish the same row on another. Current per-model status is in the baseline.

| ID | Verbatim criterion | Executable verification and required evidence |
|---|---|---|
| AC01 | A recognizable, geometrically credible model matching the selected official build. | Load that model's real assets; capture final Studio/Technical and source-aligned representative views. Review major frame, wheels, gears, motor/sensor shapes, mounts and wiring against the locked source. Reject substitutes and unresolved major silhouette/structure deviations. |
| AC02 | A verified component inventory. | Reconcile source introductions, repetition, prepared devices and reused modules with stable instance IDs and count categories. Test robot/sample totals and every family quantity, including four-pin additions. Surface VEX conflicts; never force an invented total to pass. |
| AC03 | Complete documented assembly coverage. | Machine-check every documented numbered step maps to at least one meaningful source-backed operation. Physical operations identify participating instances; a genuine source camera-only turn may use a presentation-only align operation with empty part/transform/staging arrays, required camera preset and source evidence. Reject vacuous no-effect coverage. Wiring/reuse operations may add zero new parts. Account for unnumbered preparation separately. Compare documented/implemented/verified step sets and exact edition. All required steps must be implemented and verified before complete status. |
| AC04 | Animated placement of individual components or appropriate mounting subassemblies. | Sample endpoints and intermediate times through every operation type; verify actual instance motion along continuous insertion/rotation/fastening paths, internal rigidity for mounted subassemblies, staged-to-installed transition and no simultaneous completed reveal or teleport. Browser captures include difficult insertions and module joins. |
| AC05 | Accurate placement and orientation for validated parts. | Validate attachment hole/axis/face alignment, units, source-native origins, quaternion normalization, insertion direction/depth and final poses against independently evidenced dimensions/CAD/measurements. Capture discrepancies; no floating or unexplained gaps/duplicates/intersections. Unknown placements remain unverified. |
| AC06 | Reversible, deterministic assembly playback. | Run random timestamps, forward/reverse traversal, zero/final/replay, scope boundaries, mid-operation seeks and parent changes. Same timestamp must produce identical hierarchy, transforms, active/installed flags, counts and source state, independent of playback history/frame partitioning. |
| AC07 | Synchronized instructions and timeline. | Playwright selects steps and mapped source figures, scrubs in both directions and checks actual instruction/source/hardware/selection/count output. Test restarted printed numbering, reference-only pages and pages mapping to multiple operations. Camera obeys manual override. |
| AC08 | A useful exploded view. | Toggle at initial, intermediate and final states; meaningful mechanical separation/relationships without hierarchy/count/source mutation. Exit restores the exact saved time, selection and assembly pose. Fit/isolate remain useful; no implicit jump to complete assembly. |
| AC09 | Part identification and inspection. | Ray-pick geometry and select inventory rows; verify stable instance, corrected family, known ID or explicit unknown, geometry ID, source/confidence, parent/connections/mount points, outline and accessible text. Inspect duplicate-family, staged and installed instances; isolate and exit without changing assembly state. |
| AC10 | A functional post-assembly demonstration. | Gate until full robot completion, then exercise the model-specific real hierarchy/DOF/object/sensor scenario below and deterministic reset. No replacement model, invented actuator or unlabeled extension. VEX remains blocked until permission and reconstruction prerequisites are satisfied. |
| AC11 | Automated tests. | Run permanent graph/BOM/transform/timeline/consumer regressions and Playwright scenarios against each actual model. Record command, revision and result; a generated test file, zero-test run, skip or wiring-only assertion is not a pass. |
| AC12 | Source and license documentation. | Audit exact source/edition/hash, instance/operation references, provenance categories, component/dependency notices and public-asset contents. Browser Sources links work. No private manuals/page images/benchmark assets or unauthorized VEX conversion/use enter app assets, including localhost development. |

A VEX blocked-state UI test can pass its limited assertion that the blocker is shown and no mesh is fetched. It **cannot** pass VEX AC01–AC11, turn them into skipped-success, or make the five-build product complete. AC12 may separately be verified for its source record; the current baseline claims no such app verification.

## Coverage records and graph/BOM invariants

Maintain a per-build report with the required fields: **Documented steps; Implemented steps; Verified steps; Modeled components; Verified components; Geometry confidence; Outstanding deviations**. Include absolute IDs, not just percentages. Separate sample-step/component coverage from robot coverage and unnumbered preparation. For VEX, keep unresolved physical totals null/unknown rather than use CAD occurrences as the denominator. Store scope and evidence with each count; a 100% shape-family crosswalk is not 100% assembled-component verification.

The data/compile suite must reject or explicitly report:

- Duplicate build/document/step/operation/instance/connection IDs; missing referenced parts, parents, geometry, materials, source records, camera targets or joints. All required final transforms exist and contain finite values; quaternion length is one within declared numerical tolerance; scale/defaults and scene units are consistent.
- Cyclic dependencies or parent graphs, operations referencing nonexisting dependencies, missing prerequisites at operation start, conflicting ownership of a part and overlapping incompatible operations. Validate disconnected modules only where the source actually builds them separately. The initial/final hierarchy and all parent changes are valid.
- Missing documented-step mappings, vacuous no-effect operations counted as coverage, altered edition step numbering, battery/warning pages counted as invented numbered steps, or merged index2019/lesson2021 data. A genuine source camera-only align operation is valid only with the required camera preset, source evidence and empty part/transform/staging arrays; test that it changes no physical transforms or counts and respects manual camera override. Wiring and reused-module operations can add zero new units without losing coverage.
- Geometry paths outside the authorized asset set, unresolved LDraw dependencies, missing mesh/substituted primitive, missing materials/attribution, or conversion that destroys fixed subpart colors, native origins, BFC/mirror handling or root scale/orientation.
- BOM discrepancies by family/category. Cross-check per-step callouts against introduced instances; reused modules never add their children twice; integral device cables/prepared units remain scoped correctly. Only inventory lines marked `tracked` feed physical totals; `reference-only` source records retain conflicting quantities without being summed again. Internal rotor/body render nodes are not extra source inventory. A source unknown/conflict is a visible unresolved record, not a fabricated reconciliation.
- Installed/remaining counts outside range, a four-pin operation adding one, staged parts counted as installed, a later fastening counted as another part, or robot/sample quantities merged. Test exact installation timestamp and immediately before/after it in forward and reverse. Verify initial/final totals against the scoped evidence, not advertised kit counts.
- Missing final part, duplicate visible hardware, disappearing source-supported component, unstable final assembly, or non-rigid internal movement during a rigid subassembly mount.

Consumer regressions must cover contextual crosswalk corrections: Advanced Driving Base `black-angle4x4` uses gray 63869 rather than an invented bent beam; Hand short connector uses 60483 while Robot Head's same local key uses 49283; Hand grips and sorter center-hole tile use 15535; sample bricks use 39789; sorter sample z36 is distinct from the installed z28; fixed electronics/tyre colors survive conversion. Check the manifest/asset resolver and resulting render inputs, not merely the crosswalk JSON itself.

## Path, placement and joint tests

For every physical operation, sample start, end, any installation event, and intermediate times including near boundaries. Validate continuous position/quaternion paths, endpoint agreement, quaternion sign-equivalent rotation comparisons, insertion axis/orientation, no unintentional scale interpolation, and world-space continuity when parents change. Quantify continuity in millimeters/radians against the declared authored path; never describe an arbitrary collision threshold as manufacturer data. For a source camera-only operation, instead verify its presentation effect, source synchronization and invariant physical state.

For critical interfaces, verify coincident attachment points, collinear axle/pin/shaft axes, correct mating side, plausible depth and fastener head position, using source/CAD/measured evidence. Test intentionally mirrored placements, fixed colors, right-handed root conversion and stable native origins; LDraw's 0.4 mm/LDU is approximate. Resolve unexplained floating parts, significant gaps or impossible intersections. A visual review is needed where contact geometry is not safely inferable from a bounding box.

Joints use the same actual hierarchy as assembly. Test fixed/revolute/prismatic constraints where present, pivot/axis placement, zero pose, configured demonstration bounds and coupling. Hand and sorter closed-loop linkage residuals remain within an independently justified tolerance through their full demonstration range; gear relationships/rotation direction and moving motor-body mounting must be correct. Encoder targets are not mechanical stops. Missing verified pivots/limits block the relevant accuracy claim; they are not solved by clamping arbitrary values.

## Determinism and transport test protocol

Use each actual model's compiled engine with a fixed recorded seed. Sample at least 100 pseudo-random finite timestamps plus every operation/source-step/install-event boundary and just before/after it. For each t compare:

1. Direct sampling into a fresh frame.
2. Sampling after forward playback from zero.
3. Sampling after reverse playback from final time.
4. Sampling after shuffled seek order, replay and simulated low/high frame-rate time partitions.

Compare per-instance and internal-node transform values, parent IDs, visibility/active/installed flags, connection state indexed by stable compiled connection IDs, robot/sample/fastener counts and operation/source IDs. Test wiring connection events just before/at/after their timestamps in both directions, without adding inventory. Pure sampling at exactly equal t should be numerically identical; cross-browser or GPU comparisons need documented tolerances and must not excuse history-dependent CPU state. Camera view and presentation offsets are separately tested because user-owned camera state is intentionally independent, while physical part transforms must remain unchanged by them.

Test Play step ending exactly at its next boundary, Play all stopping at final, Reverse stopping at zero, fractional Previous/Next semantics, pause/resume without jumps, all speed settings, milestone seeks, scrubbing while playing and background-tab elapsed time. Enter invalid/nonfinite time through boundary tests and verify the defined rejection/clamp contract without NaNs reaching the renderer. Repeating zero/final seeks must neither allocate a growing scene nor duplicate hardware. Switching render modes, selection, labels, explode, isolate and source-only pages does not alter assembly time/physical state.

## Browser interaction suite (Playwright)

Run against the actual SvelteKit app and real model assets, with semantic roles/labels rather than internal callback spying. Use engine-reported stable IDs/time only as corroborating diagnostics; assertions must observe the relevant consumer's DOM, scene projection/selection or capture as appropriate. Fail on console errors, uncaught rejection, missing geometry, failed model request and unexpected WebGL context loss. Await app-ready/settled state, not arbitrary sleep. Do not mock a successful model load in place of the shipped model.

| Scenario | Actions and observable assertions |
|---|---|
| Catalog / load | Find all five real names, manufacturer/edition/category/complexity, scoped source counts and accurate availability. Select each available model and observe its own instruction/inventory/geometry. VEX shows blocked metadata, no invented count/preview/action and no runtime CAD/mesh request. |
| Initial inventory | Verify appealing real staged parts, family quantities, total/installed/remaining/sample separation and unknown-ID disclosure. Select repeated instances and see unique IDs. |
| Step controls | Play step from zero and a mid-step position, observe continuous actual part movement, stop boundary, required hardware/count updates and source text. Test Play all/Pause/Resume/Reverse/Previous/Next/speed/milestone, including first/final disabled states. |
| Scrub / replay | Seek arbitrary and exact boundary times in both directions while paused and playing; verify count/source/selected-instance state and repeatable captures. Confirm no residual in-flight transforms after replay. |
| Selection / inspection | Pick a visible part and select corresponding inventory row; inspect identity/source/parent/mounts; focus/isolate/exit isolate. Search inventory, toggle labels/relationships/education overlays and verify no physical-state change. |
| Camera | Exercise orbit/pan/zoom, Reset, Fit whole, Fit selected subassembly and Focus operation; verify useful framing and unchanged robot transforms. Manipulation disables auto; step change does not override it; Resume auto restores following. Test pointer/touch equivalents and controls usable without right-click. |
| Manual synchronization | Select source-linked steps/figures and assert exact document/page/printed-step/current hardware. Browse a reference-only page and verify unchanged time; resolve multiple mapped figures explicitly. Scrub updates sources without silently opening unrelated books. Official links are valid source URLs; no manual scans are fetched from the app. |
| Studio / Technical / Explode | Toggle modes at partial/final time; same counts/source state and geometry. Explode preserves/restores saved progress and makes relationships understandable. Fit/isolate still work. |
| Simulation | Locked at zero, partial step, partial reconstructed model and incomplete final robot; never unlocked by explode. At full eligible completion execute the required per-model scenario; operate commands, observe correct actual joints/sensor/object state, reset and return to identical completed assembly. |
| Responsive / accessibility | At 1440×1000, 1024×768, 768×1024, 390×844, 320×568 and phone landscape, plus 200% zoom: no horizontal document overflow, usable scene/transport/drawers, reachable warnings/source/selection, no clipped Pause. Keyboard-only full workflow, focus restoration, input guards, semantic names, screen-reader status, contrast and reduced-motion behavior. |
| Resource lifecycle | Alternate model loads/modes repeatedly, pause/hide/background/resume, resize and unmount. No duplicate canvases/listeners/loops, stale selection, growing memory, old model motion or leaked geometries/materials/textures. |

Keyboard coverage includes `[`, `]`, Space, R/F/X/L/T/I/?, Escape, native slider arrows/Home/End, inputs/selects/contenteditable, IME composition, dialog-local keys and modified browser shortcuts. Space on a focused button triggers only that button. Focus cannot vanish into canvas or an offscreen closed drawer. Use an automated a11y smoke check plus actual keyboard and contrast inspection; an empty scanner result is not complete accessibility verification.

## Model-specific final scenarios

All scenarios require actual completed assembly and verified relevant pivots/mounts/bounds. Label app-authored interaction rules and demonstration ranges. None currently has app execution evidence.

| Build | Required scenario and assertions | Important failure cases |
|---|---|---|
| Advanced Driving Base | Drive the actual assembled chassis through a small deterministic obstacle course; independent drive commands produce differential motion; course contact prevents impossible pass-through. Exercise both unloaded Medium output tools independently; show both Color Sensor signals and reset robot/course. | No strafing, imaginary tool attachment, replacement vehicle, invented calibrated sensor model or accumulating wheel/pose drift. |
| Robot Hand | Coupled one-coordinate jaw/linkage grasps, holds and releases a source-appropriate/app-labeled sample; attached object remains coherent with contact/hand motion, release restores independent object state; reset. | No independent fingers, invented Force Sensor, broken loop closure, object pickup at a distance or fixed fake force claim. Source program/control discrepancy stays visible. |
| Quality Check Robot | Actual integrated two-coordinate expressive head responds to a color input/inspection event with source-linked movement/eye light; repeat/reset event and pose. | No invented distance-triggered lesson behavior or hidden arbitrary port-to-axis mapping; added accept/reject rules explicitly labeled extension. Respect moving upper motor-body hierarchy. |
| Package Sorter index2019 | Run complete pickup/color-check/transport/drop of prepared packages using yaw A, linked fork lift F and Color Sensor D. Verify object support and linkage throughout cycle and reset to consistent initial state. | No conveyor, independent claw, fake generalized official classifier, z36 in the z28 transmission, swapped editions or encoder target presented as safe stop. Preserve source SVG/Python differences. |
| V5 Clawbot historical2018 | **Blocked until lawful geometry use and complete reconstruction.** Then drive/turn with actual drivetrain, actuate arm/coupled claw and pick up/transport/release an object; reset. | No permission bypass via localhost/placeholder mesh, powered wrist/strafe, Rev6 notch/wiring imported into historical2018, unverified total ratio/payload/limits, or CAD occurrence count masquerading as BOM. |

## Required browser captures and visual review

For every implemented full model capture: (1) first source step, (2) meaningful intermediate step, (3) difficult attachment/fastener/linkage/module integration step, (4) final assembly, (5) partial or final Explode, (6) Technical, (7) eligible simulation including interaction. Also capture catalog, selected part/inspector, mobile drawers and visible keyboard focus. First/intermediate/difficult/final captures include both the scene and synchronized source/count UI; a scene-only thumbnail cannot establish source synchronization.

Choose and record actual step IDs after their verified data exists; do not invent a difficult step number now. For partial slices capture all implemented source steps and clearly label missing final/simulation evidence. A partial slice capture cannot satisfy a complete model's seven-state set. Keep official manual/page comparison material private; publish only original app captures and authored commentary when authorized assets permit it. Review geometric discrepancies, visibility of active attachment, repeated hardware, color/outline readability and source uncertainty rather than accepting a screenshot merely because it is attractive.

## Performance, bounded resources and release evidence

**Target** approximately 60 FPS on declared capable hardware with acceptable integrated-GPU interaction; it is not a measured claim. Record device/GPU/browser, canvas size, device pixel ratio, quality mode and scene counts. Measure actual frame-time distribution (median and high percentiles), dropped frames/long tasks, scrub-to-render responsiveness, load/decode time, draw calls, triangles, geometries/textures and memory where browser tooling supports it. Publish observed values and limitations; a headless software-rendered run does not establish real integrated-GPU performance.

Exercise worst-case final/exploded/technical scenes, active simulation and rapid scrubbing; compare to paused idle behavior. Use shared immutable static geometry/materials, instancing where compatible with picking, bounded pixel ratio/adaptive quality and disposal/reference lifetime ownership. Test a resource plateau over repeated model switches and mount/unmount cycles; investigate monotonic growth rather than inventing a universal memory ceiling before asset conversion exists. Frame sampling reuses its output buffer; sampling/transport tests catch avoidable per-frame allocation and static mesh recreation. Quality reduction may change shadows/AA/resolution, never remove required parts, alter counts or silently swap geometry.

Release evidence must contain the per-model coverage report and outstanding deviations; permanent unit/integration/browser results; source-aligned actual-browser captures; exercised accessibility/responsive/performance observations; asset/source/license audit; and explicit unresolved prerequisites. A blocked or materially unverified robot remains incomplete. No skip, optimistic percentage, successful build or appealing preview can override that boundary.
