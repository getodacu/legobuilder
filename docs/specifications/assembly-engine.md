# Assembly engine

Status: implementable contract, not a claim of shipped playback. The full five-build acceptance scope remains required; the VEX permission blocker and incomplete placement reconstruction remain visible. Shared declarations live in `src/lib/types/model.ts`; no robot constants belong there. Source baseline: [fidelity requirements](../research/fidelity-requirements.md), [source register](../research/robot-sources.md), and the [contextual part crosswalk](../research/lego-part-crosswalk.md).

## Deep module and public interface

`src/lib/assembly/engine.ts` owns validation, compilation, timeline lookup, absolute trajectory evaluation, hierarchy composition and installation accounting. It imports no Svelte or Three.js. Consumers use these functions, with shared function types declared in the schema:

```ts
compileAssembly(model: RobotModel): CompiledAssembly
createFrame(compiled: CompiledAssembly): AssemblyFrame
sampleAssembly(compiled: CompiledAssembly, timeMs: number, out: AssemblyFrame): AssemblyFrame
getStepAtTime(compiled: CompiledAssembly, timeMs: number): StepTime | null
getStepTime(compiled: CompiledAssembly, stepId: string): StepTime
```

Compile once per selected model; allocate a frame once per consumer. Sampling mutates and returns that same frame, never the model or compilation. `CompiledAssembly` exposes stable model-array-order `partIds`, `subassemblyIds`, `connectionIds`, and optional-prop `simulationObjectIds`, duration, timeline boundaries and model; private compiled channels remain engine-owned, not another public schema. A frame created for another compilation is rejected even if lengths coincide. Every output buffer and the counts object must remain the original frame-owned lane; foreign or incorrectly sized lanes are rejected before hierarchy evaluation or any output mutation. Independent frames may sample the same compilation without interference.

All time inputs must be finite. Reject NaN and infinities before mutation; clamp finite times to `[0, durationMs]`. Unknown step IDs throw a descriptive error. A zero-step model has duration zero and no current step. Step intervals are half-open `[start,end)` except the final endpoint belongs to the final step. At an exact boundary the next step is current; the preceding step's end-state has already committed. `getStepTime` returns the stable index, ID, start and end; `getStepAtTime` shares sampling's validation/clamping. UI Previous/Next use these boundaries, not rounded percentages or printed step numbers that restart in different books.

## Model authoring

All scene-facing transforms use right-handed Y-up millimeters, normalized `[x,y,z,w]` quaternions and explicit unit scale `[1,1,1]` unless an asset-level conversion justifies otherwise. No per-part recentering. Instances retain stable research IDs, with manufacturer IDs omitted when uncertain; geometry IDs identify actual assets, never substitute for catalog identity.

Steps are ordered, source-linked authored summaries. A printed numbered instruction, an unnumbered preparation, a source-reference-only page and a presentation action are distinct. A camera-only source instruction still has a source-linked timeline step, but no invented part rotation. Steps may contain concurrent operations or sequential stages; `startMs` is relative to the step and durations are explicit. Their duration defines a whole positive-duration step; a reference-only page has no step. Step numbering remains book-local in source evidence. Optional milestones group real step IDs without changing them.
`AssemblyStep.action` distinguishes assembly, view, wiring and reuse independently of whether the source instruction is numbered. A `view` step requires a camera preset and a source-linked presentation-only `align` operation with empty participant/transform/stage arrays; it must not rotate physical parts or increase counts. Wiring operations reference existing devices/cables even with no new inventory. Reuse/merge operations move existing subassemblies coherently. Other empty no-effect records cannot claim documented coverage.


An operation includes the required original fields and a typed motion supplement. The operation's participants identify stable parts and/or subassemblies. Each participant has absolute world-space start/end poses; a parent change includes parent-local before/after poses. No delta-only `rotateBy`, accumulating tween, or state inherited from the previously sampled frame is allowed. Fixed children retain local poses under a moved subassembly. A merge reparents the subassembly root, preserves descendant identities and internal transforms, and never adds its parts to inventory again.

`Subassembly.localTransform` describes the initial parent-local frame, not a completed world pose. Consumers needing completed module roots must sample the assembly at `durationMs` and read `frame.subassemblyTransforms` by `compiled.subassemblyIds`; replaying the original parent tree or composing initial local frames would miss later motion and merges. These world poses come from the same hierarchy evaluation as the part poses.

`PlacementEvidence` separates the documented relationship from the origin of its numerical placement: `acquired-cad`, `measured-attachment`, `diagram-derived`, or `presentation-only`. Source instructions can document which beam attaches without publishing its matrix. Confidence is explicit and does not promote a diagram-derived pose to dimensionally verified. An unknown required pose is a reconstruction blocker, not a guessed zero transform. Connection points are part-local frames; connection evidence records attachment type and checked/unchecked fit separately.

## Trajectories and mechanical explanation

A motion is a list of stages, each with a relative start and duration and explicit participant endpoints. Validate finite normalized transforms and non-overlap for the same moving node; independent nodes may move concurrently. Static intervals hold the last absolute endpoint. Linear and cubic Bézier paths are evaluated by normalized stage time, with explicit world-space controls. Quaternion interpolation takes the shortest orientation path; intentional multiple turns are supplied separately as `Spin` so a full-turn quaternion cannot silently erase screw rotation.
Stage start times are operation-relative and stage durations must fit the containing operation; operations are step-relative and must fit the containing step. Dependencies are a DAG and each dependency must finish before its dependent operation starts. The original string-valued operation easing accepts only the implemented `linear` and `smoothstep` vocabulary at validation, rather than executing arbitrary strings. For eased progress `u` and world-axis spin `S(u) = axisAngle(axis, 2π*turns*u)`, evaluate orientation as `S(u) * slerp(qFrom, inverse(S(1))*qTo, u)`. This preserves signed full turns and fractional turns while reaching the explicit endpoint exactly; quaternion sign equivalence is accepted.


Insertion uses a normalized world-space axis and nonnegative depth in millimeters. The axial endpoints and depth must agree within an authoring tolerance; approach, alignment, insertion and settling can be separate stages. Fastening uses the same axial path plus explicit signed turns, axis and duration. Spin is composed relative to the interpolated orientation and must reach the declared final orientation modulo whole turns. A seated fastener may spin with zero translation; a press-fit pin must not receive fake screw motion. Different source evidence can support the attachment and the presentation-only timing/path. Authored timing is not a real assembly-time estimate, tool clearance proof or collision guarantee.

Installation is a single milestone per inventory instance, stored as a step-relative time. It occurs when the instance is committed to its first prepared assembly, not every time that assembly is remounted. Membership in the model and installation are separate; staged future parts can be visible without counting as installed. Preparation/device assemblies stay one callout unit when that is the declared inventory basis. Validate unique milestones and forbid absent, duplicate or out-of-step events. At time `t`, an instance is installed iff its event time is `<= t`; this rule is independent of operation playback direction.

## Frame and performance contract

`AssemblyFrame.transforms` is a reused `Float64Array` with exactly `partIds.length * 10` entries: position xyz, quaternion xyzw, scale xyz, in scene space. `installed`, `active`, and `visible` are reused byte arrays in the same order. `active` means participating in a currently running operation, not installed or selected. `visible` is authored staging state, not UI isolate state. Sampling overwrites every output lane, including flags and counts; no stale state may survive a backward seek. `counts` is a reused object, with separate robot/sample installed and total units; totals mean authored inventory coverage, not whole-source completeness.
`AssemblyFrame.subassemblyTransforms` is a reused `Float64Array` of exactly `subassemblyIds.length * 10` entries in the same position/quaternion/scale layout, containing actual scene-world subassembly poses at the sampled time. It includes nested descendants and roots reparented by completed merges. Creation samples time zero; every later sample overwrites the entire lane, including reverse and zero resets, without allocating another hierarchy evaluator or output buffer.
`CompiledAssembly.internalNodes` supplies stable part/node bindings for actual articulated asset internals. `AssemblyFrame.internalTransforms` is another reused ten-number buffer in that order, containing node-parent-local transforms; ordinary assembly sampling resets these to their source-local asset poses and simulation can derive rotor/body articulation there. This channel does not create new inventory parts and is consumed by the same renderer. Camera preset `framing` means vertical field of view in degrees for perspective, or visible vertical span in scene millimeters for orthographic projection; `transitionMs` is finite and nonnegative.
`Joint.internalBinding.geometryNodeId` identifies a real rotor node in the bound part's geometry; it is not a body mesh or another inventory unit. The external joint owns the actual moving child. With `movingSide: 'rotor'`, the motor body stays fixed and the rotor rotates by the joint delta about the authored joint pivot. With `movingSide: 'body'`, the motor body part/subtree follows the child while the rotor countertransforms to remain fixed relative to the joint parent. Body connection frames and labels therefore follow the body, which must not be rotated a second time. Ordinary assembly sampling restores the source-local internal transforms.
`CompiledAssembly.connectionIds` indexes the reused `frame.connected` byte array. A connection commits at its `installedByOperationId` endpoint; an undeferred fixed connection is initially connected. Sampling reconstructs this state in reverse as well, so zero-new-part wiring is a meaningful state transition without inventing hardware. `InventoryLine.accounting` selects tracked lines versus conflicting/reference-only records: tracked quantity equals its instance-ID count, and every modeled instance occurs in exactly one tracked line. Reference-only quantities are never added to frame totals.

External app-authored demo/course props belong only to optional `RobotModel.simulationObjects`, each with `id`, `name`, `geometryId`, `materialId`, `initialTransform`, and `evidence`. Their IDs must be unique and cannot collide with part or subassembly IDs; geometry, material and finite normalized initial transforms are validated. They are not official BOM instances, installation milestones, or assembly-operation participants. `CompiledAssembly.simulationObjectIds` indexes `AssemblyFrame.environmentTransforms` (world packed-ten poses) and `environmentVisible` (bytes). Creation and ordinary assembly sampling restore initial poses and hide every prop; simulation can update these same buffers without creating replacement robot parts.

`SimulationScenario.objectEvents[].objectSubassemblyId` identifies either a sample subassembly or an external simulation-object ID. Event `transform` is parent-local for attachment and world-space for release. Optional `capture` specifies actual holder/object local contact pairs, `maxGapMm`, `poseToleranceMm`, `angleToleranceRad`, and evidence; simulation owns capture/contact and continuity validation. Closed-loop `referenceJointValues` use `[driverJointId, ...dependentJointIds]` order. `SimulationFrame.compiled` identifies the owning simulation compilation, distinct from its reused `assembly` frame.

`differentialDrive.axleCenterInRoot` is the physical wheel-center midpoint in root-local millimeters; `initialTransform` remains the completed assembly-root world pose. The root need not lie on the axle (the Advanced Driving Base is anchored at its Front module). Simulation integrates motion about the axle frame and converts back to the root frame, rather than treating the root origin as the turning pivot. Assembly compilation validates the axle offset as a finite xyz vector.



Compile validates unique IDs, references, asset/material existence, finite positive durations, finite numbers, normalized axes/quaternions, unit scale unless justified, acyclic parents at every reparent event, unambiguous writers, trajectory endpoints, source/step mappings, installation uniqueness and declared inventory reconciliation. Report author-facing errors with model/step/operation/instance IDs. Never silently drop malformed operations or repair unknown transforms. Compilation builds lookup tables and topological orders once. Sampling reuses scratch storage, performs no per-frame static mesh rebuild, source parsing, geometry loading, array creation, map construction or Svelte object-tree replacement. Three.js adapters copy values into existing matrices only where needed.

## Determinism and UI ownership

Absolute-time sampling must produce equivalent output for direct seek, forward replay, backward replay, repeated time, and random seek orders. No `Date.now`, previous-frame interpolation, randomness or imperative animation state participates. The UI owns the wall-clock mapping to time, speed, playback direction and stop boundary. Pause freezes time; manual seek pauses before sampling. Play step stops at the selected step end, Play all at the final endpoint, reverse decreases absolute time and does not claim a safe physical disassembly process. Reduced motion can jump between endpoints without changing the sampled state or event accounting.

Source navigation does not itself seek: only an explicit mapping from a source figure to a step may do so. Selection is a stable instance ID. Camera, labels, studio/technical/inspection modes, isolation and exploded offsets are renderer presentation, never engine transforms. Exploding preserves the underlying sampled time and installation counts. Simulation begins from the completed supported assembly using the same hierarchy; it does not rewrite assembly source data.

## Required checks for implementation phase

Exercise one miniature authored model through direct/repeated/forward/backward/random seeks, concurrent insertion and spinning fastener, multistage placement, camera-only step, nested merge and exact installation boundaries. Compare reused buffers and derived counts with a direct reference sampler, including zero-duration model, invalid finite times, duplicate IDs/install events, unknown references, overlapping writers and reparent cycles. Then reconcile each complete LEGO model against its locked source inventory and every mapped step. These are required future checks, not checks performed by this specification.
